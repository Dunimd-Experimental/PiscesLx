## 1. 问题的陈述：step 0 的寻址与内容是两个独立随机测度

现状（读码得到，非推测）：

- 块 i 的内容 `Mem_i ∈ R^{M×d}`，经 `memory_norm`（LayerNorm）后由块自己的 `query/key` 打分读取，
  读出的方向再经 `out` 投回主干宽度：`u_i = W_out · LN(Mem_i)` 的第 0 阶近似取行均值
  `m̄_i = mean_j LN(Mem_ij)`，记 `u_i = normalize(W_out m̄_i) ∈ R^d`。
- 寻址侧：`s(h) = (W_q h / √k) · R^T`，`R ∈ R^{N×k}` 即 `traces`，**独立**初始化。

因此在 step 0，"哪些 h 会命中块 i"（由 `R_i` 的方向决定）与"块 i 读出来会往哪个方向调制主干"
（由 `u_i` 决定）是**两个互相独立的随机变量**。寻址把隐状态空间做出的划分，与内容能力空间做出的划分
没有任何相关性——池的 314B 在第一千步之前等价于"随机查一个随机答案"。

**为什么这在本项目里比在 VQ-VAE 里更致命**：驻留下限（`block_min_dwell_tokens ≈ 17`，
由 5 ms/token 检索预算在 T2 里反推出来）使早期错误分配**被粘住**：一个区域一旦被错配，
至少 17 个 token 连续吃到同一个错误调制，而这 17 个 token 的梯度又共同强化同一个错误 trace。
VQ-VAE 没有这个结构性质，所以它的码本初始化差只是收敛慢； ours 会让"被激活块参与训练"
在早期退化为"少数几个恰好赢了 argmax 的块参与训练"。这是 §3 池覆盖率上不去的结构性原因。

## 2. 机制：把 trace 定义为块内容签名的**保序代表**（已实现口径）

对每个块 i：

```
m̄_i  = mean_j LN(Mem_ij)                     # ∈ R^d，内容一阶质心
u_i   = W_out · m̄_i                          # 该块对主干的典型贡献方向（不做单位化）
W     = query_proj.weight                    # ∈ R^{k×d}，寻址度量（step 0 取初值即固定）
R̃_i  = (W Wᵀ)⁺ W u_i                         # ∈ R^k：u_i 在寻址度量下的最小二乘代表
R_i   = (ρ / rms) · R̃_i                       # rms = sqrt( mean_i ‖R̃_i‖² )，**全局唯一**缩放
```

关键等式（即 §5 的 r1 断言，实测 1.2e−6）：

```
<W h, R_i> = (ρ / rms) · <h, P u_i>,        P = Wᵀ (W Wᵀ)⁺ W  是到 row(W) 的正交投影
```

即 step 0 的寻址排序**就是**内容排序在寻址子空间里的像。`k ≥ d` 时 `row(W) = R^d`、`P = I`，
排序**逐点精确**（实测 Kendall τ = 1.000）。

**为什么缩放必须全局唯一**（这是实现中撞到的第一个反例）：若像最初写的那样对每个 trace
单独单位化（`R_i = ρ·R̃_i/‖R̃_i‖`），则 `<W h, R_i>` 相对 `<h, u_i>` 多出一个**逐块不同**的因子
`1/‖R̃_i‖`——排序被这个因子打乱。实测 τ 从 1.000 掉到 **0.865**，`r2` 当时判失败；改成全局
`rms` 后回到 1.000。寻址要的是"全局可比的分数"，任何逐块归一化都会破坏可比性。

## 3. 命题（要证的三条）

**引理 1（step 0 对齐性，已实测为恒等式而非不等式）** `P` 是正交投影，故对任意 h，
`argsort` of `<W h, R_i>` 与 `argsort` of `<h, P u_i>` 完全相同（τ=1，实测）；
`P = I` 当且仅当 `k ≥ d`（此时恒等）；`k < d` 时排序在正交补方向上按 `k/d` 的比例损失，
τ 单调下降（实测：`k=d`→1.000，`k=d/8`→0.227，见 r2b）。
⇒ **初值不是随机划分，而是内容能力划分的 k 维保序像。**

**定理 R1（step 0 覆盖率下界）** 若 `{P u_i}` 在 `row(W)`（`k` 维）上是 ψ-分散的，则 step 0
每个块的命中测度 `≥ c·(1 − Nψ)/N`，于是 B·T 个 token 期望调取的**不同块数**
`≥ min(N, B·T)·(1 − Nψ)`。独立随机初始化只给出与内容无关的 `≈ 1 − e^{−B·T/N}`——这正是今天的病。
（机检：r2/r2b 实测两个数，不引公式当结论。）

**定理 R2（与 T5 的相容性）** RPI 只改 `R` 与块内 `W_out/memory` 的**初值**（块由 `_make_block(id)`
确定性重建），不改任何前向公式，故 T5 的 `‖Δh‖ ≤ κ‖h‖` 原样成立（实测 r5：κ=0.075 不变）。
⇒ 改初始化而非加机制，无冗余、无新失效模式。

## 4. 代价、ρ 与**一条新的设计律**

- **一次性代价**：`O(N·(M·d + d²))`，逐块流式，峰值只驻留一个块。0.01B 层实测
  **543 ms / 64 块**（rows=96, d=64，见 r6），随块尺寸线性。**每次训练一次，不是每步。**
- **ρ 的推导而非调参**：取 `ρ = λ·√k / rms(W)`（`rms(W)=‖W‖_F/√k`），使单位距离查询的典型分数
  `ρ‖Wh‖/√k` 与滞回 `λ` 同阶——否则滞回/驻留完全主导或完全不主导初始划分。实测 r3：
  `rms|R_i| = 13.9732` 与公式 `ρ = 13.9732` 相对误差 5e−8，公式恒等 0。
- **新发现的设计律（trace 宽度必须与 d 同阶）**：对齐精度由 `k/d` 决定，不是由 `ρ` 决定。
  `τ ≈ (2/π)·arcsin(√(k/d))`；要 `τ ≥ 0.6` 需 `k/d ≥ 0.65`。而 `configs/model/*.yaml` 目前
  把 `block_trace_dim` 固定为 **256**，7B 的 `hidden_size = 4096` → `k/d = 0.0625` →
  预期 `τ ≈ 0.11`，**RPI 在旗舰档几乎不起作用**。修正方向是让 `k` 随 `d` 放大到 `≈0.65d`
  （4096→~2700），trace 常驻体积仍只有 `N·k = 628×2700 ≈ 1.7M` 元素 ≈ 3.4 MB，**代价可忽略**。
  这条律已作为「§7 后续」记录，`block_trace_dim` 的取值需在阶段 6 架构定稿时随 `d` 重算。
- **诚实边界**：RPI 只保证 step 0 的"内容—寻址"对齐，**不保证**该内容有用
  （内容由训练数据决定）。它消灭"初值把寻址变成纯随机"，不消灭"池里没东西"。

## 6. 与已有工作的差别（§8.4，敢被反驳的写法）

VQ-VAE/k-means 码本初始化、以及 kNN-LM 类检索扩展，都做过"码本对齐编码输出"。三条实质差别，
若其中任何一条被证明可归约，我不申报这项创新：

1. 我们的码不在**待重构的潜空间**，而在**打分的对偶空间**：对齐目标是块对主干的*贡献方向*
   （经 LayerNorm、`out` 投影、tanh 有界化），不是要被重建的向量；因此"对齐"的定义是
   排序保序（引理 1 用 Kendall-τ），不是欧氏距离。
2. 注入是**乘性+加性且有 T5 界**的条件参数化，不是加权平均的检索值；错配代价有界、正确收益
   依赖内容与查询的几何一致性 ⇒ 初值几何是训练可达性的前置，而非收敛速度问题。
3. **驻留下限**（T2 从 5 ms/token 预算反推的 `D_min≈17`）使早期错配自增强且持续 ≥17 token；
   VQ 家族没有这个耦合，所以对它们初始化是"锦上添花"，对我们它是**可行性条件**。
