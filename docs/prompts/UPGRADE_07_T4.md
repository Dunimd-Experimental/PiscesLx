# 07 · T4 硬件约束

## T4 规格
- **GPU**：NVIDIA Tesla T4
- **显存**：16GB GDDR6
- **架构**：Turing（compute capability 7.5）
- **Tensor Core**：支持 FP16，不支持 BF16 原生加速
- **带宽**：320 GB/s

## 7.1 训练要求

**7B 模型必须在 T4 上进行完整、全精度、快速的训练。**

- **全精度**：训练使用 FP16 或 BF16 精度（不用 INT4/INT8 量化训练作为主要方式），确保训练质量
- **完整训练**：能完成完整的训练流程（前向、反向、优化器更新）
- **快速**：训练速度尽可能快，通过架构设计和工程优化实现

**你必须解决的挑战**：
- 7B 参数 × FP16 = 14GB 权重，加上梯度和优化器状态，16GB 显存极其紧张
- 需要创新的内存管理：GaLore、梯度检查点、CPU 卸载、混合精度、选择性冻结
- 可能需要架构层面的创新：使模型训练时显存占用最小化
- Flash Attention 在 Turing 架构上可能受限，需要替代方案

**鼓励的技术方向**：
- GaLore（低秩梯度投影）
- 梯度检查点（Gradient Checkpointing）
- CPU Offloading（优化器状态卸载到 CPU）
- 混合精度训练（FP16 + FP32 主权重）
- 选择性层冻结 + 渐进解冻
- LoRA / QLoRA 微调支持（作为可选模式，非唯一模式）
- 任何你发明的创新技术

## 7.2 推理要求

**7B 模型必须在 T4 上实现完美推理。**

- **完美推理**：高质量输出，无损精度，支持全部模态和全部上下文长度
- **1M 上下文推理**：KV Cache 管理（Paged Attention, 量化 KV Cache, 滑动窗口 + 混合策略）
- **314B 知识块池（查）**：模型自身权重，由 628 个 0.5B 知识块组成，推理时稀疏激活约 0.5B 量级，不将全部 314B 常驻激活显存；被激活的知识块以注入方式短暂影响激活路径，用完退回非激活态。**具体调取机制是本项目必须自主发明的核心创新（业界无现成参考），不得预设为 mmap / codebook / 预取等任何特定实现**——本质是调取模型自身的知识块权重，不是查询外部数据库
- **快速生成**：Speculative Decoding, Medusa, 或其他加速技术
- **量化推理**：4-bit / 8-bit 量化推理支持，但不作为唯一模式
