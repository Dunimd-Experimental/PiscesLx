## 10.2 禁止事项

1. **禁止 MoE → Dense 退化**：任何规模都不允许从 MoE 退化为 Dense
2. **禁止降低能力**：升级不能导致任何现有能力丧失
3. **禁止盲目删除**：删除任何代码前必须理解其作用和依赖关系
4. **禁止无测试提交**：关键修改必须有测试验证
5. **禁止倒退式优化**：不能以降低性能/质量为代价简化实现
6. **禁止忽略 T4 约束**：7B 必须能在 T4 上训练和推理
7. **禁止半成品**：每个模块必须完整实现，不能留 TODO 或 stub
8. **禁止破坏全家族**：修改不能只考虑 7B，必须兼顾所有规模
9. **禁止任何形式的模拟/占位/伪造**：
   - **禁止 mock 实现**：所有算法必须真实、可运行、有数学依据，绝不允许 placeholder、stub、mock、假数据、假结果敷衍
   - **禁止伪旗舰**：不能只是换名或加 wrapper 就声称已升级。每个算法必须有实质性改进和正确实现
   - **禁止模拟运行**：训练和推理测试必须真实执行，不能用模拟输出代替。T4 上无法运行就说明原因并修复，不要伪造结果
   - **禁止学术造假**：不能编造不存在的论文、算法或学术参考
10. **禁止缺乏创新**：不允许仅做"换名重写"或"简单搬运"，不允许用"优化"冒充"创新"（调参/换优化器/加 wrapper 都不算创新）。必须进行**全新的架构、全新的算法、更优的实现**层面的实质性创新
11. **禁止降低评测目标**：目标锁定为对标 DeepSeek-V4-Flash-0731 的 85%~95%（核心项 ≥90%），达不到时只能向上迭代提升，绝不允许下调或降低标准
12. **禁止不做自主迭代**：不允许"跑一次就交差"。必须建立设计→实现→训练→评测→分析→创新→重训的闭环，循环到达标为止
13. **禁止硬编码**：
    - 路径、超参数、模型尺寸、专家数量、维度、vocab size、层数等所有可配置参数**必须通过配置文件或配置数据类传入**
    - **禁止 magic number**：代码中不能出现未经解释的数字常量。必须用时定义为有意义的命名常量并附注释
    - **禁止硬编码路径**：所有文件路径通过配置或环境变量传入
    - **禁止硬编码模型 ID/名称**：模型名、分词器路径、数据集名等通过配置传入
    - **禁止硬编码设备/平台**：不能写死 `cuda:0` 或特定 GPU ID，通过配置或环境变量指定
    - **例外**：数学常数（π、√2）、算法固定参数（如 softmax 的 1.0 缩放）不受限，但需注释说明
14. **禁止违反强制编码规范**（详见 `UPGRADE_06_CODING.md`）：禁止 `model/` 内类不以 `Yv` 开头；禁止 `model/` 外类不以 `PiscesLx` 开头；禁止模块顶层裸函数；禁止标准库 `logging`（必须 dmsc 0.1.8）；禁止保留重复代码；禁止缺少或篡改版权头、打乱 future import 位置；禁止 `Pisces`/`pisces` 违规拼写
15. **禁止引擎接入其他模型**（详见 `UPGRADE_04_ALGO.md` 4.5）：禁止引擎加载/调用/代理任何外部模型；禁止以任何其他模型为基座继续训练/微调；蒸馏仅允许离线数据生成阶段，teacher 不得进入引擎
16. **禁止只改模型不改引擎**：模型修改必须同步训练引擎和推理引擎，禁止孤儿式修改
17. **禁止只改模型和引擎、其他不管**（详见 4.4）：任何模型改动必须同步升级项目下所有相关内容——配置、CLI、工具链、数据管线、服务、评测、文档、注释、测试。禁止旧架构残留，禁止新旧并存
18. **禁止保留 document / agent 作为独立模态**（详见 3.3.1）：必须彻底移除出模态体系（agent 回归文本层面工具调用），禁止残留 doc/agent 模态编码器、配置项、数据管线、评测项
19. **禁止浪费算力**：纯逻辑推理/思考/设计时禁止空占 GPU，必须释放资源
20. **禁止无推导留痕**：逻辑推理和数学推导必须有 Markdown 书面记录并归档到对应文件夹
21. **禁止数学证明造假或缺失**（详见 9.7）：禁止任何创新缺少配套的严格数学证明；禁止错误证明（逻辑漏洞、循环论证、"显然成立"式敷衍）；禁止证明与实现脱节；禁止编造定理/引理/不存在的结论
22. **禁止架构堆砌与冗余**（详见 9.8）：禁止为"看起来创新"堆砌无意义、功能重叠的组件；禁止新旧组件功能重叠还并存；禁止只加不减（堆砌）或只减不加（退化）
23. **禁止伪造成达标的假象**（详见 `UPGRADE_01_ROLE.md` 诚实原则）：禁止为了"看起来达标"而伪造分数、日志、权重、证明。未达标必须诚实报告；但报告失败不等于停止——必须继续死磕其余部分（详见诚实原则，这与"不允许停止"不冲突）
24. **禁止跳过 Fermi 可行性前置**：动手前必须对核心指标做量级核算，不得在明知物理不可达的情况下硬着头皮实施而不报告

## 10.3 强制创新要求

本任务**强制要求全面创新**，不是可选加分项，而是核心验收标准。

### 10.3.1 创新是硬性要求
- 不仅优化升级，还必须**发明新机制、新算法、新架构设计**
- 简单地把现有算法从论文复制到代码**不算创新**——需在理解原理基础上改进、组合、或发明全新方法
- 特别是 T4 约束下，现有技术无法满足要求时，必须**发明新解决方案**

### 10.3.2 创新方向（不限于此）
- **架构创新**：重新设计 MoE 路由、查算分离注入方式、模态统一框架
- **算法创新**：改进注意力复杂度、KV Cache 管理、训练内存优化、推理加速
- **系统创新**：T4 显存管理新方案、314B 知识块池寻址/调取机制创新
- **融合创新**：将多个已有技术进行非平凡组合，产生新能力
- **理论创新**：有数学上的新发现或推导，鼓励探索

### 10.3.3 创新验证
- 每个创新必须有**严格的数学证明**（详见 9.7）支撑，正确、真实、可验证
- 每个创新必须有**实验验证**（在 T4 上真实运行）
- 不能凭空声称"创新了"——必须有可复现的证明与效果
- 创新点必须在架构设计文档中明确标注，说明与现有方法的区别和优势

### 10.3.4 创新与"优化"的严格区分（不可混淆）
**本任务不接受"优化"冒充"创新"。** 优化是在已有轨道上跑得更快；创新是铺一条全新的轨道。

| 维度 | 优化（不达标，禁止交差） | 创新（必须做到） |
|------|------------------------|-----------------|
| 架构 | 调层数、维度、头数、专家数 | 重新设计模型的组织范式/信息流 |
| 算法 | 调超参、换优化器、换激活函数 | 发明前所未有的机制/结构/运算 |
| 实现 | 加 wrapper、换名字、拼接口 | 相同能力下的数量级效率跃升 |
| 系统 | 调 batch、精度、并行度 | 全新的显存/调度/寻址方案 |

**判定标准**：如果你能在一篇现有论文里找到完全相同的做法，那就不是创新。创新必须是"查不到先例"或"有实质性的非平凡改进"。

### 10.3.5 创新是进化的唯一路径
高目标（9.4）的唯一目的就是**逼出进化**。分数定得低，你不会创新；分数定得高，你不得不创新。
- 目标是接近 DeepSeek-V4-Flash-0731 的真实水平（85%~95%）
- 靠"优化"不可能达到——7B 参数量远小于对手
- 唯一出路：**用全新的架构、全新的算法、更优的实现，实现质的跃迁**
- 这就是"进化"：不是把现有东西做得好一点，而是变成更强的物种

### 10.3.6 自主架构探索：不止 MoE 一条路
**未来的架构不会只有 MoE 一条路径。** 必须自主探索、自主开辟新路径（详见 9.8）。
- **自主探索**：MoE、查算分离、SSM、混合注意力只是"已知地图"上的点。有权去地图外探索全新范式
- **自主增加**：现有架构不足以支撑目标时，可自主新增架构组件——新模块、新计算范式、新参数组织
- **绝不冗余**：探索与增加必须在"不冗余"前提下进行——禁止功能重叠、禁止堆砌、合并优先、正交设计
- **既精简又强大**：真正的进化 = 在更精简的结构里爆发出更强的能力。只加叫堆砌，只减叫退化，**又加又减、精简而强大才叫进化**
- **MoE 是底线**：探索不等于抛弃 MoE。所有规模仍须是 MoE 稀疏专家模型

## 10.4 执行顺序

### 阶段 0：调研与情报收集（先查资料，别空想）
1. 搜索并研读顶尖旗舰模型技术报告（DeepSeek、GPT、Claude、Gemini、Qwen、Kimi、Llama、Grok）
2. 检索 2026 年 10 月前最新研究论文（arXiv、NeurIPS/ICML/ICLR/ACL/CVPR 等顶会）
3. 阅读相关开源实现、技术博客、架构分析
4. 深入理解 DeepSeek 查算分离架构、当前 SOTA MoE 设计、T4 优化最新实践
5. 建立情报档案（Markdown 归档留痕），作为后续所有设计的依据
6. 明确哪些旗舰设计可借鉴、哪些需创新、哪些不适用于 T4 约束
7. **Fermi 可行性核算（强制前置）**：在动手前，对核心硬指标做量级估算（Fermi estimate），确认它们在 T4 + 可用资源下**物理上可达**。至少覆盖：
   - **显存**：7B 全精度训练的最小显存下界（权重 + 梯度 + 优化器状态 + 激活）≈ 多少 GB？T4 只有 16GB，缺口靠什么补（GradCheckpoint/GaLore/Offload/选择性冻结）？
   - **算力**：达成目标 Loss 所需 token 数 × 单步耗时 ÷ 可用 GPU 小时 = 需要多少墙钟时间？与 Kaggle 三账号 + 启智的可用额度是否匹配？若缺口，靠什么（更多账号/更快算法/更优数据）补齐？
   - **吞吐/延迟**：1500 tok/s 训练、35 tok/s 解码的物理上限是多少？当前硬件带宽（320 GB/s）下，达到该吞吐的显存访问下界推算是多少？是否自洽？
   - **上下文**：1M 输入 + 1M 输出在 16GB 显存下的 KV Cache 显存下界是多少？靠什么（量化 KV/分页/稀疏）压到 ≤ 14GB？
   - 若核算发现某项**在现有资源下不可达**，必须**立即报告并说明所需额外资源**（见 `UPGRADE_01_ROLE.md` 诚实原则），而不是硬着头皮假装可行
