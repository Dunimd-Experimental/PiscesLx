# 04 · 算法工程 · 全项目同步 · 引擎红线

## 4.1 合并重复算法

当前项目实现了大量算法，存在功能重叠和冗余。你的任务：

1. **全面审计**：列出所有已实现算法（`model/core/`, `model/moe/`, `model/multimodal/`, `model/reasoning/` 中每个模块）
2. **识别重复**：找出功能重叠的算法（多个注意力变体、多个融合机制、多个路由策略）
3. **合并去重**：将重叠算法合并为单一旗舰实现
4. **确保不丢失能力**：合并后的算法必须覆盖被合并算法的全部功能

## 4.2 旗舰化每个算法

**每个保留的算法都必须是 2026 年旗舰级别。**

- 升级到最新版本/最新论文实现
- 确保实现质量：正确性、效率、数值稳定性
- 添加充分的测试和验证
- 文档化每个算法的学术参考和设计理由

当前已实现的 2026 旗舰算法（需保留并升级）：mHC（流形约束超连接）、Kimi AttnRes、PathMoE、Phi-Balancing、HydraHead、LCA（Linear Complexity Attention）、DSpark、MoVE、SparseCut、CSA/HCA、MrRoPE、HiCL Router、LayerRoute、CoMeT、Engram、Seirênes、SAGE、SEAL、A-Evolve、mHC-lite。

## 4.3 创新空间

你不仅可优化现有算法，还可：**实现全新算法**（基于 2026 最新研究）、**进行架构创新**（重新设计整体架构）、**自行迭代**、**发明新机制**（现有算法无法满足 T4 约束时）。

**创新是鼓励的，倒退是禁止的。**

## 4.4 全项目同步升级（强制，不只是模型和引擎）

**绝对禁止"只改模型，其他不管"。** 每当模型架构发生任何改变，**项目下所有相关内容都必须同步适配与升级**，不允许"改了模型但其他地方还是旧的"。

**必须同步升级的范围（不止于此）**：
- **训练引擎**：`opss/train/`, `opss/optim/`, `opss/quantize/`, `tools/train/`
- **推理引擎**：`opss/infer/`, `model/generation/`, `model/core/cache.py`
- **配置系统**：`configs/`（所有 YAML）、`model/config.py`（YvConfig 及全部子配置类）
- **CLI 入口**：`manage.py` 全部相关命令
- **工具链**：`tools/`（benchmark, data, monitor, test, cache, dev, infer, publish 等）
- **多模态管线**：编码器、融合、生成、预处理、后处理
- **数据管线**：`tools/data/`、数据加载、预处理、tokenize、collate
- **推理服务**：`serve` 相关后端服务
- **评测系统**：benchmark、评测脚本、指标计算
- **文档**：README、架构文档、API 文档
- **注释与类型**：所有 docstring、类型注解、注释中引用旧架构/旧模态/旧参数的地方
- **测试**：所有单元测试和集成测试

**要求**：
- 任何一处修改，都要**主动排查全项目影响面**，把所有依赖该改动的地方一并更新
- 不允许留下"孤儿"（引用已删除/已修改模块的残留代码）
- 不允许"新旧并存"（旧架构代码、配置、文档与新的同时存在造成混乱）
- 升级是**全局的、彻底的、一致的**
- **所有内容必须形成整体统一架构，不允许互相分离**：模型架构、训练引擎、推理引擎、配置、工具链、数据管线、服务、评测必须是一套自洽整体，无缝衔接，绝不各自为政

## 4.5 引擎禁止接入其他模型（强制红线）

**训练引擎和推理引擎绝对不允许接入其他任何模型。**

- **禁止接入外部模型**：引擎中禁止加载、调用、代理任何外部/第三方模型（包括提供的 ~12 个蒸馏模型）
- **禁止以其他模型为基座再训练**：不允许以任何其他模型（Qwen、Llama、DeepSeek 等）为 base 进行继续训练或微调
- **PiscesL1 必须是独立的、从零构建的模型体系**——所有架构、权重、训练流程都必须是 PiscesL1 自己的
- **允许蒸馏**：可使用其他模型进行**知识蒸馏**（teacher → student），让其他模型作为 teacher 提供软标签/监督信号，但**学生模型始终是 PiscesL1**，其他模型不进入 PiscesL1 的引擎
- **蒸馏边界**：teacher 只在离线蒸馏数据生成阶段使用，产物是训练数据/软标签，而非可被引擎加载的模型组件
