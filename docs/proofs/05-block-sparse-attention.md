# 证明 5：块稀疏注意力的因果性、精确性与复杂度

对应实现：`model/core/token_sparse_attn.py::YvTokenSparseAttention`
（配置 `model/config.py`：`tactic_block_size` `tactic_blocks_per_query`
`tactic_cumulative_target` `tactic_n_bins`）。登记项 `docs/audit/00` A62。

## 0. 记号

序列长 `T`，块宽 `b = tactic_block_size`，块数 `n = ⌈T/b⌉`，补齐长 `P = n·b ≥ T`。
预算 `m = min(tactic_blocks_per_query, n)`。
查询块 `i` 覆盖查询位置 `[ib, (i+1)b)`；键块 `j` 覆盖键位置 `[jb, (j+1)b)`。
低秩选择维 `d_s = head_dim/4`。记 `S(i)` 为查询块 `i` 选中的键块集合。

选中规则（实现）：先令 `C(i) = {j : jb < ib}`（**严格在前**的块），得分
`σ(i,j) = ⟨q_i, k_j⟩ / √d_s`，其中 `q_i` 取查询块 `i` 的**第一行**低秩查询向量，
`k_j` 取键块 `j` 的低秩键均值；由直方图法取累积质量达到 `ρ = tactic_cumulative_target`
的阈值 `θ_i`，得 `E(i) = {j ∈ C(i) : σ(i,j) ≥ θ_i}`；再取 `E(i)` 中得分最高的 `m` 个并
**强制并入对角块 `i`**，得 `S(i)`，`|S(i)| = m` 且元素互异。

---

## 1. 定理 1（严格因果）

**结论.** 对任意 `t`，把输入 `x_t` 改为 `x'_t` 只改变位置 `≥ t` 的输出。

**证明.** 只需证对每个查询位置 `p`，其可见键集合 `V(p) ⊆ {0,…,p}`，且 `V(p)` 不依赖
任何 `x_t (t > p)`。

(i) *键集合.* `p ∈ [ib,(i+1)b)`，`V(p) = ∪_{j∈S(i)} [jb,(j+1)b) ∩ {0..p}`。
- `j ∈ S(i) \ {i}` ⇒ `j ∈ C(i)` ⇒ `jb < ib ≤ p` ⇒ 块 `j` 的全部键 `< ib ≤ p`，合法。
- `j = i` ⇒ 块内取 `{0..p} ∩ [ib,(i+1)b)`，即位置 `≤ p`，合法。
故 `V(p) ⊆ {0..p}`。**（块级 + 块内两级因果已覆盖全部键）**

(ii) *选择不依赖未来.* `S(i)` 由 `σ(i,·)` 决定。
- 键侧 `k_j`：`j ∈ C(i)` ⇒ 块 `j` 的键位置 `< ib`，对 `p ∈ [ib,(i+1)b)` 全部 `≤ p`。
- 查询侧 `q_i`：取块 `i` 的**第一行**，其位置为 `ib ≤ p`。
故 `σ(i,j)` 与阈值 `θ_i` 只由位置 `< ib` 的查询和位置 `< ib` 的键决定，`ib ≤ p`，
不含任何 `x_t (t > p)`。因此 `S(i)`、`V(p)`、以及位置 `p` 的输出都与 `t > p` 无关。∎

**注（这条性质不是免费的）.** 若查询侧改用整块均值 `q̄_i = mean_{p∈块 i} q_p`，
则 `q̄_i` 依赖块内全部行，第 `ib` 行的选择就会依赖第 `(i+1)b−1` 行 —— 因果被破坏。
实测（`perturb tok 12`）证实：改前 `past frozen = False`，改后为 `True`。

---

## 2. 定理 2（预算足够时精确等于稠密因果注意力）

**结论.** 若 `m ≥ n`，则本层输出与标准稠密因果注意力**逐元素相同**。

**证明.** `m ≥ n` ⇒ `|S(i)| = n`。
- `C(i) = {0,…,i−1}`（共 `i` 个），并入对角 `i` 后最多 `i+1` 个候选；
- `|S(i)| = n ≥ i+1`（因 `i ≤ n−1`）⇒ 当前候选全部入选，即 `S(i) = {0,…,i}`。
于是查询块 `i` 的可见集合为 `∪_{j≤i} 块 j` 的全部键，再由块内因果掩码裁到 `≤ p`，
即 `V(p) = {0,…,p}`。softmax 的输入集合与稠密因果一致，权重与输出因此一致
（唯一的差异是运算次序带来的浮点误差）。∎

**实测.** 同权重下 `m = n = 8`：`max|output − dense_causal| = 1.043e-07`（fp32）。
同权重 `m = 2`：块 0 的行与稠密逐位相同（`S(0) = {0}`，块 0 本就只能看自己），
其余行出现差异 —— 稀疏确实在丢键，而不是"掩码了但算全量"。

---

## 3. 定理 3（无 NaN）

**结论.** 对任意掩码（含整行被填充掩码全掩、或 `T` 不整除 `b` 产生的补齐列），
本层的 softmax 输入必有一个有限元，输出有限。

**证明.** 由定理 1(i)，位置 `p` 的自身键 `p ∈ V(p)`，即无掩码时对角位置有限。
掩码只可能把条目置 `−∞`。设某行全部条目为 `−∞`。实现中该行所属查询块 `i` 的对角块
`i ∈ S(i)`（强制并入规则），且存在槽位 `s*` 与块内位置 `u*` 使 `key_global[...,s*,u*] = p`
（因为 `p ∈ [ib,(i+1)b)` 且块 `i` 完整出现在某个槽位）。实现把该单个条目置 `0`，其余
保持 `−∞`。softmax 在 `{0, −∞, …, −∞}` 上等于 `(1, 0, …, 0)`，有限。
其余行按定义至少有一个有限元，softmax 有限。
实现另用 float32 累加 softmax（`scores.float()`）后再转回，避免 fp16 在长行上的上溢。
原实现用 `scores == scores.max()` 补"最大值"位：整行 `−∞` 时该比较匹配**所有**条目，
softmax 得到 NaN —— 定理 3 的失败模式，已由本次改写消除。∎

---

## 4. 定理 4（复杂度）

**结论.** 设 `T` 为序列长、`D = head_dim`、`d_s = D/4`、每头每层：

| 项 | 本实现 | 稠密 |
|---|---|---|
| 选择 | `O(n² d_s)` | — |
| 读取键值 | `O(T·(m b) · D)` | `O(T² D)` |
| 分数阵 | `O(B·H·n·b·m·b)` | `O(B·H·T²)` |
| 峰值额外显存（单槽） | `O(B·H·T·D)` | `O(B·H·T²)` |

二次项的比值为 `m·b / T`。以默认 `b = 64, m = 8` 计，`T = 4096` 时为 `12.5%`、
`T = 16384` 时为 `3.1%`，即长上下文下二次项降一个量级；选择项 `n² d_s = (T/b)² d_s`
在 `T = 4096, b = 64, d_s = 32` 下为 `131k`，比 `T²/2 = 8.4M` 小 64×，不构成新瓶颈。

**代价（诚实边界）.** 当 `T ≤ m·b` 时比值 `≥ 1`，本实现不比稠密省——此时
`m·b ≥ T` 意味着 `S(i)` 已覆盖全部候选，按定理 2 它**退化为精确稠密**，只多付一次
选择开销。因此该配置下必须启用长上下文才划算（本机 0.1B 训练用 `T ≤ 512`，
故 `use_tactic` 默认关闭，`use_tactic=False` 不受影响）。

## 5. 假设与失效情形

- **A1**：`head_dim` 可被 4 整除（`d_s = head_dim/4`）；实现用 `max(1, head_dim//4)`
  兜住退化情形，代价是选择分辨率下降。
- **A2**：调用方语义 —— 位置 `≥ T` 的补齐列永远非法（实现强制 `−∞`）。
- **A3（被显式拒绝而非静默放过）**：方阵掩码 `[T,T]` / `[B,T,T]` 不再被翻译成键侧偏置，
  因为因果已由定理 1 内生；把因果掩码的第一行当键侧有效性会误杀全部键。若调用方传入
  `[B,1,T]`/`[1,T]` 形式的填充掩码，其行数必须是 `1` 或 `batch`，否则实现直接抛错。
- **失效模式**：`m` 过小会丢真实长程依赖（近似，不是错误），差异由
  `tactic_cumulative_target` 控制；定理 2 给出该近似的收敛端点（`m ≥ n` 时无误差）。
